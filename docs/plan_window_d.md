# 下阶段规划：预警时机曲线拓展（窗口 D）

> 版本：2026-10-31 · 状态：设计定稿，尚未开工
> 本规划是窗口 C 完成后的延伸，**不修改已完成的三部分主线结论**。

## 1. 为什么是它（定位）

现有三部分已经闭环：

```
位宽曲线（RQ1-4）→ 三元绕崖（RQ5）→ 开口前预警（RQ6）
```

RQ6 留下一个未拆开的二义性：探针在 MMLU-Pro 上只有 0.572、在 TruthfulQA 上有 0.693。
这个差异有两种解释：

| 解释 | 含义 | 现状 |
|---|---|---|
| (a) 位置问题 | 观察点（提示词末位）离决策太远，信号尚未形成 | 无法验证 |
| (b) 信号问题 | 模型内部确实没有可读的不确定性 | 无法验证 |

拓展实验用 Qwen3 的 thinking 模式（`enable_thinking=True`）把观察点**沿思考过程向后推移**，
把这两种解释分开。**无论曲线升不升，结论都比现在更强**：

- 曲线明显上升 → 是"位置问题"，同时定量回答"需要多少思考量才能预警"；
- 曲线保持平坦 → 是"信号问题"，原来的负结果升级为强结论（观察点已经推到决策之前了）。

## 2. 研究问题（RQ7）

> 把探针的观察点从提示词末位沿思考过程推移到答案生成前，预警能力（AUROC）如何变化？
> 思考是否让"模型知道它不知道"这件事变得可读？

## 3. 与已有结果的衔接（必须引用）

- MMLU-Pro：探针 0.572 [0.514, 0.631] < 置信度 0.604 → 已知失效
- TruthfulQA：探针 0.693 [0.639, 0.739] > 置信度 0.575 → 已知有效
- 已知中间层 L21 最优；题型难度基线已解释 IFEval 假象
- 已有局限条目："探针特征只用末位 token"——本拓展正是针对它的补丁

## 4. 任务拆解

| 编号 | 任务 | 产出 | 预计耗时 |
|---|---|---|---|
| D1 | `probe_collect_thinking.py`：chat template + thinking 生成；对 `prompt+思考前缀` 在 0/25/50/75/100% 处各做一次前向取末位激活 | `results/probe_think_<基准>.npz` | 编码 1h + 采集 3.5~5.5h |
| D2 | 分析脚本：分位置训练探针（嵌套 CV 同 RQ6 口径），画"预警时机曲线" | `results/probe_timing.md` + 曲线图 | 2h |
| D3 | 对照与混淆控制：think vs 非 think（复用现有数据）；按"思考比例"与"绝对 token 数"两种切法各报一遍 | 同上 | 0.5h |
| D4 | 报告 3.10 节 + RQ7 入列 + 摘要备注 | `docs/report.md`、`docs/proposal.md` 修订 | 1h |
| D5 | 演示扩展 Tab「思考模式」：流式思考 + 探针分随思考推进的走动表盘 | `scripts/app.py` | 2h |
| D6 | 三部分主页集成（把量化曲线/三元/探针放进同一 Gradio 页面）+ 报告定稿 | `scripts/app.py`、`docs/report.md` | 2~3h |

**采集规模**：TruthfulQA 250 + MMLU-Pro 250 = 500 题。
每题的代价 = 1 次 thinking 生成（约 200~600 token）+ 5 次前缀前向。
实测参考：0.6B CPU 约 25~40 秒/题 → 500 题约 **3.5~5.5 小时**（挂后台过夜）。

**降级路径**（时间紧张时依次执行）：

1. 题量砍到 100 + 100（约 1.5 小时），曲线走向仍可读；
2. 观察点砍到 0/50/100% 三点；
3. 只做 TruthfulQA 一维（但要放弃 MMLU-Pro 对照，损失一半信息量）；
4. 放弃 D5 演示扩展，只交付报告。

## 5. 分析方法（与 RQ6 完全同口径）

- 每个观察位置各训练一个逻辑回归探针（L2，C=0.1，类权重平衡，标准缩放）
- 嵌套交叉验证（外层 5 折出 AUROC，内层 5 折选层），1000 次 bootstrap CI
- 对照：同一批题的置信度基线（平均 token 对数概率）与题型难度基线
- 差异检验：DeLong；位置间比较用同一样本配对口径
- 已知陷阱（从 RQ6 继承）：
  - 题型难度基线必须保留（thinking 不会消除题型效应）
  - 思考长度是混杂变量 → 双口径切分
  - thinking 可能改变正确率 → 同时报告正确率与 AUROC，区分"更会答"与"更自知"

## 6. 验收标准

- [ ] 500 题全部完成，错误行 = 0

- [ ] 测试全绿；新脚本有对应单元测试

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| thinking 在部分题上不触发（模型直接作答） | 统计触发率并单独报告；不触发的题并入 0% 位置组 |
| 0.6B 的 thinking 质量差、思考很短 | 如实报告平均思考长度；短思考时 75% 位置缺失就退到三点 |
| 曲线在 MMLU-Pro 上依旧平坦 | 这是有效结论（信号问题被证实），按预案撰写 |
| CPU 采集时间超过 6 小时 | 降级路径 1~2 |
| chat template 与主实验不一致 | 本拓展本身就以 thinking 模式为新分布，报告中单独声明，不与 RQ6 混报 |
